FEATURE BLUEPRINT: Battle Action Announcement Message
======================================================
Target branch: feature-improve-title-2
Repo: C:/Users/Ted/Projects/daq-game


WHAT IT IS
----------
During battle execution, a brief text message appears on the battlefield
each time an action fires. It announces what is happening in plain terms:

  "[CharName]  [ActionName]  on  [TargetName]"

For self-targeting actions (buffs, heals, stances):

  "[CharName]  [ActionName]"

The message fades in, holds briefly, then fades out. It is completely
separate from the BattleLog (which still does its own scrolling log).
This is purely a battlefield overlay — a surface-level announcement.


WHY
---
The player compiled all actions before battle. By the time execution
starts they already know the order. But they still need a quick spatial
confirmation of "who is doing what to whom" on each step — especially
with multiple enemies and staggered speed orders. This text provides
that without needing any projectile or line animation.

Reference: similar to announcement banners in Dragon Quest and Darkest
Dungeon that appear briefly during action execution.


DESIGN DECISIONS
----------------
- Appears centered on the battlefield, between EnemyZone and BattleQueue
- Fades in fast (~80ms), holds ~900ms, fades out ~300ms
- Color: blue (#4da6ff) for player actions, red (#e94560) for enemy
- Does NOT delay combat — completely parallel to the battle loop
- Does NOT replace the BattleLog — both coexist independently
- No portal needed — rendered in normal layout flow


HOW TO GET THE ACTION DATA
--------------------------
BattleQueue.jsx exports simulateExecutionOrder(). Import it:

  import BattleQueue, { simulateExecutionOrder }
    from '../components/battle/BattleQueue';

Call it to peek at the next action without dispatching anything:

  const allActions = simulateExecutionOrder(gs.characters, null);
  const center = allActions[0];

From center:
  center.name          — the action name
  center._char         — the acting character object
  center._char.name    — acting character's name
  center._char.faction — 'player' or 'enemy'
  center.target_id     — id of the target character

Find the target:
  const target = gs.characters.find(c => c.id === center.target_id);

Determine if self-targeting:
  const isSelf = center.target_id === center._char.id;


IMPLEMENTATION
--------------

Step 1 — State (add to BattleScreen.jsx):

  const [announcement, setAnnouncement] = useState(null);
  // Shape: { text: string, color: string, key: number } | null


Step 2 — Effect (add as its own separate useEffect in BattleScreen.jsx):

  useEffect(() => {
    if (gs.phase !== 'BATTLE') { setAnnouncement(null); return; }

    const showAt = 80;   // ms delay before showing
    const holdMs = 900;  // ms the text is visible
    const fadeMs = 300;  // ms fade-out duration (match to CSS)

    const t = setTimeout(() => {
      const allActions = simulateExecutionOrder(gs.characters, null);
      if (allActions.length === 0) return;

      const center = allActions[0];
      const target = gs.characters.find(c => c.id === center.target_id);
      const isSelf = center.target_id === center._char?.id;
      const color  = center._char?.faction === 'player' ? '#4da6ff' : '#e94560';

      const text = isSelf || !target
        ? `${center._char?.name}  ${center.name}`
        : `${center._char?.name}  ${center.name}  on  ${target.name}`;

      const stepKey = gs.stepCount;
      setAnnouncement({ text, color, key: stepKey });

      setTimeout(() => {
        setAnnouncement(prev => prev?.key === stepKey ? null : prev);
      }, holdMs + fadeMs);

    }, showAt);

    return () => clearTimeout(t);
  }, [gs.phase, gs.stepCount]);


Step 3 — CSS (add to src/battle/animations.css):

  @keyframes announceFadeIn {
    from { opacity: 0; transform: translateX(-50%) translateY(6px); }
    to   { opacity: 1; transform: translateX(-50%) translateY(0);   }
  }
  .battle-announcement {
    position: absolute;
    left: 50%;
    transform: translateX(-50%);
    white-space: nowrap;
    pointer-events: none;
    font-family: monospace;
    font-size: 0.72rem;
    font-weight: bold;
    letter-spacing: 0.18em;
    text-transform: uppercase;
    text-shadow: 0 0 12px currentColor;
    animation: announceFadeIn 80ms ease-out forwards;
    z-index: 50;
  }

  Note: fade-out is handled by setAnnouncement(null) removing the element
  from the DOM after holdMs + fadeMs. No extra CSS class needed.


Step 4 — JSX (in BattleScreen return, between EnemyZone and BattleQueue):

  {/* Battle Action Announcement */}
  {announcement && (
    <div style={{ position: 'relative', height: 0, overflow: 'visible' }}>
      <div
        key={announcement.key}
        className="battle-announcement"
        style={{ color: announcement.color, bottom: '0.5rem' }}
      >
        {announcement.text}
      </div>
    </div>
  )}

  Place this between <EnemyZone ... /> and <BattleQueue ... />.


CRITICAL RULES
--------------
- This is its own useEffect — do NOT merge it into the battle loop effect
- Do NOT modify the battle loop useEffect (the one dispatching BATTLE_STEP)
- The battle loop must remain identical to what is on this branch
- key={announcement.key} on the div is required — forces CSS animation
  restart on each step even if the text content is the same
- Do NOT use gs.pendingAnimation for timing — that covers already-fired
  actions. simulateExecutionOrder() peeks at what fires NEXT.


VERIFY WHEN DONE
----------------
- Message appears once per action step during battle
- Blue for player actions, red for enemy actions
- Self-buff/heal shows "[Name]  [Action]" with no target
- Combat speed is unchanged — battle does not wait for the message
- Message clears when battle ends or phase changes
- BattleLog still works independently alongside this
