# Particle Effect System — Architecture Guide

A JSON-driven, Pixi.js-powered particle effect layer that sits over the React game UI.
Effects are authored visually, exported as JSON, and referenced by name from the existing
animationRegistry.js entries via a separate particleRegistry.js.

---

## Stack

```
[ Pixi canvas — particle effects overlay ]   ← position: absolute, z-index: 100, pointer-events: none
[ React UI — cards, HP bars, battle log ]
[ Background — pixel art scene ]
```

Pixi owns the visual effects layer. React owns everything else. Neither interferes with the other.

---

## Two Registries — One Per Concern

animationRegistry.js  — already exists. Owns CSS classes, SFX, floating numbers.
particleRegistry.js   — new file. Maps preset names → JSON effect file paths only.

The existing animationRegistry entries reference particle presets by name only:

```js
// animationRegistry.js
heavy_slice: {
  cssClass: 'animate-heavy_shake',
  duration: 500,
  sfx: [...],
  floatingNumber: { color: '#ff4444' },
  particles: 'physical/heavy_slice',   // ← name only, particleRegistry resolves the path
}
```

```js
// particleRegistry.js
export const PARTICLE_REGISTRY = {
  'physical/heavy_slice': 'effects/physical/heavy_slice.json',
  'physical/dual_slash':  'effects/physical/dual_slash.json',
  'fire/flame_strike':    'effects/fire/flame_strike.json',
  'ice/ice_slash':        'effects/ice/ice_slash.json',
  'lightning/storm':      'effects/lightning/storm_strike.json',
  'heal/mend':            'effects/heal/mend.json',
};
```

## Integration Plan — Start Slow

Build and verify one step at a time. Each phase is independently shippable.

### Phase 1 — Canvas only (no effects yet) ✓
- Install pixi.js and @pixi/particle-emitter
- Create EffectsLayer component: transparent Pixi canvas, full screen, pointer-events none
- Mount it in BattleScreen above EnemyZone, below nothing
- Verify: game looks identical, clicks still work, no performance hit
- Goal: prove the canvas doesn't interfere with gameplay at all

### Phase 2 — One effect, hardcoded position
- Create particleRegistry.js (empty except one entry)
- Author one JSON effect in the Pixi editor (start with: shake / physical hit sparks)
- Fire it at a hardcoded screen position (center of screen) on every shake animation
- Verify: particles appear, game still runs, CSS + SFX + floats unaffected
- Goal: prove the Pixi emitter works end to end

### Phase 3 — Position on target
- Use getBoundingClientRect() to find the target element
- Pass targetId → DOM lookup → (x, y) coordinates to EffectsLayer
- Verify: particles spawn on the correct enemy/player for each hit
- Goal: prove positioning works across all enemy slots and player portrait

### Phase 4 — Wire into the animation forEach block
- Add block #4 to the animation useEffect in BattleScreen alongside CSS/SFX/floats:

```js
// ── 4. PARTICLES ─────────────────────────────────────────────
if (config.particles) {
  const el = document.querySelector(`[data-target-id="${anim.targetId}"]`);
  if (el) {
    const { left, top, width, height } = el.getBoundingClientRect();
    spawnParticles(config.particles, left + width / 2, top + height / 2, anim.animation_mod);
  }
}
```

- Verify: each animation type fires its correct particle preset
- To disable: comment out this block. Everything else keeps running.

### Phase 5 — animation_mod runtime overrides
- Add animation_mod support to the emitter (scale, speed, color_shift)
- Tags can inject mods via INJECT_MULT / POST_ATTACK phase handlers
- Start with one example: BATTOJUTSU injects speed: 0.5, scale: 1.8

### Phase 6 — More effects (add one at a time)
- Each new effect = one JSON file + one line in particleRegistry.js
- Prioritize by how often the animation fires in combat

## Authoring Effects

Use the @pixi/particle-emitter online editor to design effects visually.
Export the JSON directly. No hand-writing required.

Each JSON defines the base effect:

```json
{
  "lifetime": { "min": 0.5, "max": 1.5 },
  "frequency": 0.008,
  "spawnChance": 1,
  "particlesPerWave": 1,
  "emitterLifetime": 0.4,
  "maxParticles": 200,
  "addAtBack": false,
  "pos": { "x": 0, "y": 0 },
  "behaviors": [
    {
      "type": "alpha",
      "config": { "alpha": { "list": [{ "value": 1, "time": 0 }, { "value": 0, "time": 1 }] } }
    },
    {
      "type": "color",
      "config": { "color": { "list": [{ "value": "f97316", "time": 0 }, { "value": "7c2d12", "time": 1 }] } }
    },
    {
      "type": "moveSpeed",
      "config": { "speed": { "list": [{ "value": 200, "time": 0 }, { "value": 100, "time": 1 }] } }
    },
    {
      "type": "scale",
      "config": { "scale": { "list": [{ "value": 1, "time": 0 }, { "value": 0.2, "time": 1 }] } }
    }
  ]
}
```

## Payload Integration

action payload references the effect name. animation_mod overrides are optional:

```js
{
  payload_type: 'PHYSICAL',
  damages: [...],
  animation: 'heavy_slice',        // maps to particles: 'physical/heavy_slice' in registry
  animation_mod: {                 // runtime overrides — optional
    scale: 1.5,                    // bigger for heavy hits
    speed: 0.8,                    // slower for dramatic moments
    color_shift: 10,               // nudge hue slightly
  }
}
```

One JSON file, infinite variations through mods:
- Crit hit → scale: 2.0
- Weakened hit → scale: 0.6
- BATTOJUTSU powered → speed: 0.5, scale: 1.8

---

## Tag/Phase Integration (Phase 5+)

Tags inject animation_mod into the payload during the existing phase pipeline:

```js
handlers['INJECT_MULT'](payload, owner, tag) {
  payload.animation_mod = {
    ...payload.animation_mod,
    speed: 0.5,
    scale: 1.8,
  };
  return { payload, consumed: true };
}
```

## Pixi Overlay Setup (React)

```jsx
import { useEffect, useRef } from 'react';
import * as PIXI from 'pixi.js';
import { Emitter } from '@pixi/particle-emitter';

export function EffectsLayer({ effectQueue }) {
  const canvasRef = useRef(null);
  const appRef = useRef(null);

  useEffect(() => {
    const app = new PIXI.Application({
      view: canvasRef.current,
      backgroundAlpha: 0,        // transparent — React UI shows through
      resizeTo: window,
    });
    appRef.current = app;
    return () => app.destroy();
  }, []);

  useEffect(() => {
    if (!effectQueue.length) return;
    const { preset, animation_mod, x, y } = effectQueue[effectQueue.length - 1];
    // load JSON from particleRegistry, apply mods, fire emitter at (x, y)
  }, [effectQueue]);

  return (
    <canvas
      ref={canvasRef}
      style={{
        position: 'absolute',
        inset: 0,
        pointerEvents: 'none',   // clicks pass through to React
        zIndex: 100,
      }}
    />
  );
}
```

## Summary

| Concern         | Where it lives                          |
|-----------------|-----------------------------------------|
| Effect design   | Pixi particle editor → JSON file        |
| Effect registry | particleRegistry.js (name → path)       |
| Effect trigger  | animationRegistry.js particles field    |
| Runtime tweaks  | animation_mod on the action payload     |
| Tag injection   | INJECT_MULT / POST_ATTACK phase (Ph 5+) |
| Rendering       | Pixi canvas overlay above React UI      |

Add a new effect: open editor, design, export JSON, add one line to particleRegistry.js. Done.
